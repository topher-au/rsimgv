title: Development desc: Source layout, building, testing and the technology behind rsimgv. ---

rsimgv is written in Rust with GTK 4 and libadwaita. It is free software under the GPL-3.0-or-later, and its source is on GitHub.

Source

  • github.com/topher-au/rsimgv, the repository.

Technology

PartUsed for
Rust, gtk4 0.11 and libadwaita 0.9The application and its interface.
MesonThe build, which runs Cargo, compiles the stylesheets with sassc, builds the GResource bundle and installs everything.
GSettings with a custom backendSettings, stored as YAML. The backend is a GObject subclass in C (native/backend.c) because the Rust bindings do not expose what is needed to subclass GSettingsBackend.
libmpvVideo playback, rendered in software or with OpenGL into memory for GTK to show.
OpenCVBicubic resampling and sharpening of pictures.
rusqliteThe metadata index and viewing history in one SQLite database.
xxhash-rustContent hashes that identify a file for its settings and history, and names for the caches.
serde_yaml_ng, serde_jsonThe YAML files and the JSON interface.
PyO3 and PyGObjectThe optional Python plugin runtime.
VapourSynth and the open-svpflow pluginsOptional frame interpolation, built from third_party/open-svpflow and embedded.

                     metadata, thumbnails
  hash.rs            hashes for cache names
  keybindings/       the action catalogue, chords and the binding table

Building and testing

./dev.sh          # rebuild and run rsimgv
./dev.sh test     # rebuild and run the test suite
./dev.sh cargo check  # run a Cargo command in the build environment
scripts/test.sh   # the same, or only tests whose names contain an argument

The tests need a display. On a machine without one, scripts/test.sh runs them under xvfb-run -a. They run on a single thread, because GTK runs on one.

Design notes

  • The browse grid is its own widget. Only the items on screen have widgets, rows are filled left to right and the block of rows is centred, so folders with many files stay responsive.
  • Thumbnails are demand-driven. A few are made at a time, and a request that nothing on screen wants any more is dropped before it runs.
  • Everything is an action. The keybinding table, scripts, notifications, plugins and the remote control interface all resolve to the same catalogue of named actions.
  • Settings apply live. The YAML file is watched, and a change made in the file, the dialog or the menu has the same effect at once.
  • A file is identified by its contents. Per-file settings and viewing history are keyed by a content hash rather than a path, so they follow a file that is moved or renamed. The metadata and thumbnail caches are keyed by path and are rebuilt when they miss.
  • Metadata is a searchable index. ffprobe output is stored as linked rows in SQLite, not as JSON or blobs, so any key at any depth can be searched across files.
