title: Files and folders desc: Where rsimgv keeps its configuration, bookmarks, playlist, per-file settings, viewing history, metadata index, thumbnail cache and sockets. ---

rsimgv keeps its data in ordinary files in standard places. Everything it writes is plain text you can read, back up and edit, apart from the SQLite index and the thumbnail cache.

Configuration: ~/.config/rsimgv/

This is $XDG_CONFIG_HOME/rsimgv if that is set. The settings file can be moved with RSIMGV_CONFIG, and the files below sit beside it.

FileHolds
rsimgv.confYour settings, as YAML. It also records the folder and file that were open when you last closed the window.
keybindings.yamlThe keys that differ from the defaults. See the bindings file.
bookmarks.yamlYour bookmarked folders, each with a name and a path.
folder_sort.yamlThe sort chosen for each folder, while Remember folder sort settings is on.
playlist.xspfThe playlist, with its items, their titles and lengths, the made and shuffled orders, which have been played and which was shown. An older playlist.m3u8 is read and moved over the first time the playlist is loaded.
file_settings/Settings for each media file; see below.
mpv/mpv's own config directory for rsimgv's player: mpv.conf and any scripts. See Configuring mpv.
plugins/<id>/config.jsonThe values of the settings a plugin declares, written by the Plugins page. A plugin can also read a config.yaml in the same folder through rsimgv.host.config_path().

The files are written atomically, so a crash or a power cut does not leave a half-written file.

Per-file settings

The viewer can keep what you did to a media file: a video's play position, speed, volume and mute state, output aspect ratio, and a picture's or video's turn and mirror, fit mode, zoom and pan. Remembered → File settings chooses which. They are found by the file's contents, not its path, so they follow a file that is moved or renamed.

A file is known by its content hash, 32 lowercase hexadecimal digits made with XXH3-128 over its size, every 64-bit little-endian word in its first and last 64 KiB, and up to eight 64 KiB samples drawn from its middle. Files too small to hold a middle sample are hashed from the first and last chunks alone. Its settings are one YAML file, file_settings/<first character>/<hash>.yaml, with every value at its root:

position: 93.5
speed: 1.25
volume: 0.8
muted: false
aspect: "16:9"
rotation: 90
mirrored: false

To forget everything remembered about your files, delete the file_settings folder.

Data: ~/.local/share/rsimgv/

This is $XDG_DATA_HOME/rsimgv if that is set. RSIMGV_DATA overrides the folder.

FileHolds
media-index.sqlite3The metadata index and the viewing history. The index holds each picture's and video's path, modification time, size, content hash, type and the metadata read from it, as linked rows that can be searched across files. The history is a table of its own, keyed by content hash, so clearing the metadata leaves it as it is.

The database uses SQLite's write-ahead log, so media-index.sqlite3-wal and -shm may sit beside it while rsimgv runs. The index is a cache and can be rebuilt; the viewing history is not, and is lost with the file.

Thumbnail cache: ~/.cache/rsimgv/

Thumbnails are PNG files in a folder per size (32, 64, 128, 256, 512, 1024 and 2048), filed under the first two characters of their name so no folder holds very many files. Video preview frames are in a frames folder beside them. Thumbnails that have not been made for ninety days are removed in the background when rsimgv starts; one that is needed again is simply made again. The whole folder is safe to delete. To stop using it, turn off Enable thumbnail cache in Performance, and thumbnails then last only as long as they are in memory.

Sockets

PathWhat
$XDG_RUNTIME_DIR/rsimgv.sockThe remote control Unix socket, when enabled. Its path can be changed in the preferences.
/tmp/rsimgv-mpv-<pid in hex>mpv's JSON IPC for the running player. Appears once a video has been opened.
