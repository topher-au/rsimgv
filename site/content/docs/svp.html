title: SVP frame interpolation desc: Smooth video playback in rsimgv with SmoothVideo Project: bundled open-svpflow plugins, output frame rate modes and options. ---

SVP (SmoothVideo Project) makes video look fluid by synthesising frames between the real ones. rsimgv runs videos played through libmpv through SVP's VapourSynth plugins, the same way SVP's own svpctl does.

{{shot prefs-videos-svp "The SVP tab of the video preferences"}}
Bundled plugins

rsimgv builds and embeds the open-svpflow VapourSynth plugins, so a separate SmoothVideo Project installation is not required. Point Plugin libraries at SVP's own directory if you would rather use its libraries instead.

Requirements

  • The mpv video backend, with an mpv build that has VapourSynth support, because rsimgv loads SVP through mpv's vapoursynth filter. The SVP page offers to switch to it when it is not the chosen one.
  • The bundled plugins, or SVP installed with its own VapourSynth plugin libraries (libsvpflow1_vs64.so and libsvpflow2_vs64.so, or the same names without _vs64) in one directory, named by Plugin libraries (video.svp.plugin-directory).
  • Optionally an NVIDIA GPU, for SVP's optical flow analysis on the GPU. Without it, SVP's CPU analysis is used.

Turning it on

  1. Open the SVP tab
    Ctrl+, for the preferences, then Videos → SVP.
  2. Choose the plugin libraries
    Leave Plugin libraries empty for the bundled ones, or point it at SVP's own directory.
  3. Switch on Interpolate frames with SVP
    It applies to videos you open from then on. V turns it on or off while watching.

Output frame rate

How the rate SVP is asked to produce is chosen is the Output frame rate:

ModeOutput rate
defaultThe source's own rate, within the limits.
fixedThe target rate, within the limits.
variableThe target rate divided by the playback speed, so playing faster does not push the output past what can be made.
display (default)Your display's refresh rate divided by the speed, so the frames shown each second match the display.

In fixed and variable, a Target frame rate of 0 means the source's rate. Whatever the mode picks is rounded to a whole number of frames a second and kept between the Minimum (60 by default) and Maximum (240 by default) frame rates. Because the target follows the playback speed in the display and variable modes, slow motion and fast forward keep the output within range.

NVIDIA optical flow

NVIDIA optical flow (video.svp.nvof, on by default) runs SVP's motion analysis on the GPU through SVP's second plugin, rather than on the CPU. Turn it off if you have no NVIDIA GPU.

Seeking and start-up

mpv reloads SVP after every seek, which would make skipping through a video wait for it. Pause SVP while seeking (video.svp.seek-bypass.enabled, on by default) leaves SVP out of the video while it is skipped through and just after it starts, and brings it back after Seconds until SVP comes back (video.svp.seek-bypass.delay, 1 second by default) after the last seek. A new video starts without SVP for the same moment. Turn it off to have SVP from the first frame, at the cost of waiting on every skip.

SVP's manager socket

SVP's libraries expect to find a local server, normally run by svpctl or SVP Manager, at /tmp/com.svpteam.svp. While SVP is on, rsimgv serves that socket itself, answering handshakes and leaving SVP's settings as they are, so no other SVP process needs to be running. Each client is served on a thread of its own, so a busy main thread does not hold up the filter.
