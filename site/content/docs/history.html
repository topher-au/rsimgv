title: Viewing history desc: How rsimgv counts views and watch time for pictures and videos, where it keeps them, and how to show and clear them. ---

rsimgv can remember how many times each picture or video has been viewed, and how long it has been watched. The totals appear in the viewer and the browse grid, and the Viewing History dialog lists recent files.

{{shot history-dialog "The Viewing History dialog"}}

What counts as a view

The viewer measures the time actually spent with an item with its own timer, so faster or slower playback counts the time actually spent: a video played at twice the normal speed adds half the time a normal-speed play of the same length would.

Pictures
A picture counts as viewed after it has been on screen for Picture view time (history.image-seconds, 5 seconds by default). 0 counts it at once.
Videos
A video counts as viewed when either Video watch time (history.video-seconds, 20 seconds by default) or Video watch percentage (history.video-percent, 10% by default) is reached in the current play. Either one is enough.
Switching off
Count pictures and Count videos choose which media is recorded, and Track viewing history (history.enabled) turns the whole feature off.

A record is kept even for a file that was not watched long enough to count as a view, as long as some time was spent on it, so the watch time adds up across short looks.

Where the totals show

  • The viewer's status bar and the media overlay can show the item's views and watch time, when Show views and watch time (history.show-stats) is on.
  • The browse view's item info can include Views and Watched fields, which start on a line of their own in the inline layout. See Item appearance.
  • Viewing History in the main menu lists the most recently viewed files, newest first, with each one's views and watch time. Activating a row opens it in the viewer, and the trash button clears the history after asking.

Where it is kept

The history is a table in media-index.sqlite3, the same SQLite database that holds the metadata index, in ~/.local/share/rsimgv (or RSIMGV_DATA). Every window shares it. A file is known by its content hash, so its history follows it when it is moved or renamed; the last path it was viewed at is kept for the list.

Clearing the history forgets the views and watch time but leaves your settings and the metadata index's cache of file details. To remove both, delete the database while rsimgv is not running. See Files and folders.
