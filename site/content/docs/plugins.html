title: Plugins desc: Python plugins in rsimgv: discovery, the manifest, the Python API, actions, menus, events, panels, settings and the bundled LLM Screenshot plugin. ---

Plugins extend rsimgv with Python: they can add actions, keybindings, menus, events and sidebar panels, and declare their own settings. Four plugins are bundled: LLM Screenshot sends the viewer's picture or video frame to an OpenAI-compatible vision model, AI Upscale enlarges pictures, LLM Chat is a chat about what you are looking at, and MCP Server lets MCP clients drive rsimgv. Every plugin is off until you switch it on.

Python support is a build option

Python plugin support is built by default when python3-embed and pygobject-3.0 are available. Configure with -Dpython=auto, -Dpython=enabled or -Dpython=disabled. The AppImage and Flatpak are built with it disabled, so they have no plugins.

Writing your first plugin

This builds a plugin that shows a notification naming the picture or video in the viewer, and logs each item the viewer changes to.

  1. Make a plugin directory and point rsimgv at its parent while you develop: 
    mkdir -p ~/dev/plugins/com.example.hello
export RSIMGV_PLUGINS=~/dev/plugins
  2. Write the manifest, plugin.yaml, in that directory. scope says where the key works: global, browse, view, image, video, playlist or tree. 
    api: 1
id: com.example.hello
name: Hello
version: 0.1.0
runtime: python
entry: plugin.py
startup: on-demand

events: [viewer.item_changed]

contributes:
  actions:
    - id: greet
      label: Greet
      description: Say which item the viewer shows.
      scope: view
      default_keys: [ctrl+alt+g]
  3. Write the plugin, plugin.py: 
    import rsimgv


class Plugin:
    def activate(self, host):
        rsimgv.host.log("info", "Hello plugin active")

    def deactivate(self):
        pass

    def invoke_action(self, action, context):
        if action != "greet":
            return
        try:
            info = rsimgv.host.call("view.info")
        except Exception as exc:
            rsimgv.notify(f"Hello: {exc}", level="error")
            return
        rsimgv.notify(f"Viewing {info.get('filename') or 'nothing'}")

    def on_event(self, name, data):
        if name == "viewer.item_changed":
            rsimgv.host.log("info", f"Viewer moved to {data['path']}")
  4. Run it. Start rsimgv --verbose from the shell where you set RSIMGV_PLUGINS. Hello is listed on the Plugins page. Switch it on with its switch there, open a picture and press Ctrl+Alt+G. The action is named plugin.com.example.hello.greet in the keybinding editor.
  5. Edit and reload. Change the notification text and save. With plugins.allow-reloading and plugins.auto-reload on, the plugin reloads on its own. Otherwise send plugins.reload over the remote control, or turn on the reload button on its row. An action that raises an error is reported as a window notification.

From here, rsimgv.host.call(method, params) runs the same methods as the remote control, such as view.info, view.screenshot, files.list and settings.get. Add contributes.settings for options, read from the config.json beside rsimgv.host.config_path(), and contributes.panels with create_panel for a widget in the sidebar or over the viewer. Do slow work, such as network requests, on a thread, and return to the GTK main thread with rsimgv.ui.idle_add, because a plugin that blocks stalls the whole window. The bundled plugins are complete examples, and LLM Screenshot is the smallest.

Where plugins live

A plugin is a directory containing plugin.yaml. They are looked for in:

  1. $RSIMGV_PLUGINS (a colon-separated list, useful while developing)
  2. $XDG_DATA_HOME/rsimgv/plugins (usually ~/.local/share/rsimgv/plugins)
  3. each $XDG_DATA_DIRS/rsimgv/plugins
  4. the directories in plugins.extra-directories

A plugin is off until its id is in plugins.enabled, so nothing runs until you switch it on. The switch on each row of the Plugins tab turns a plugin on or off at once and saves the choice. A disabled plugin's code is stopped and its panels and menu items are removed, and its keybindings report that it is disabled. The button beside the switch opens the plugin's own settings.

Reloading

Reloading is off by default, because reloading Python plugins can leak memory or crash the program. The Advanced tab has plugins.allow-reloading, which asks for confirmation. Only with it on can plugins.auto-reload watch Python files and manifests and reload a plugin when they change, and plugins.allow-individual-reload show a reload button on each plugin row. Turning allow-reloading off turns both off. The plugins.reload remote control method is always available.

The manifest

api: 1
id: com.example.hello
name: Hello
version: 0.1.0
runtime: python
entry: plugin.py
startup: on-demand

events: [folder.navigated, viewer.item_changed]

contributes:
  actions:
    - id: greet
      label: Greet
      description: Say hello to the selected item.
      scope: browse
      default_keys: [ctrl+alt+g]
  menus:
    - menu: main
      label: Greet
      action: greet
  panels:
    - id: response
      slot: sidebar.bottom
      title: Hello
  settings:
    - key: greeting
      label: Greeting
      kind: string
      default: Hello
  • api must be 1. Plugin ids may contain lowercase letters, digits, dots and hyphens.
  • Action names become plugin.<id>.<action> and can be bound in the keybinding editor.
  • Panel slots are sidebar.bottom, browse.sidebar, browse.header, viewer.overlay and preferences.plugins. Only sidebar.bottom, browse.sidebar and viewer.overlay are built so far.
    • A browse.sidebar panel is in a sidebar on the right of the browse view, outside the playlist's, and its width can be dragged. The sidebar is open while a panel in it is shown, so a plugin shows or hides its panel with container.set_visible.
    • A viewer.overlay panel is a card over the viewer's picture, in the corner given by position (top-left, top-right, bottom-left or bottom-right; top-right by default). The plugin sizes it and can hide it with container.set_visible.
  • Setting kinds are string, text, int, bool and choice. Settings are written to the plugin's own config.json and shown on the Plugins page. A choice setting takes choices; an int setting can take min and max.

The Python contract

The host imports entry and instantiates create_plugin() or the Plugin class, then calls:

class Plugin:
    def activate(self, host): ...
    def deactivate(self): ...
    def invoke_action(self, action, context): ...
    def on_event(self, name, data): ...
    def create_panel(self, panel_id, instance_id, container, context): ...
    def panel_destroyed(self, panel_id, instance_id): ...

create_panel receives a host-owned Gtk.Box and appends its widgets to it.

The rsimgv module

rsimgv.host.call(method, params=None) -> dict
rsimgv.host.log(level, message)
rsimgv.host.config_path() -> str
rsimgv.host.plugin_id
rsimgv.host.generation

rsimgv.ui.connect(widget, signal, callback) -> int
rsimgv.ui.idle_add(callback) -> int
rsimgv.ui.timeout_add(ms, callback) -> int
rsimgv.ui.source_remove(id)
rsimgv.ui.disconnect_all()

rsimgv.notify(text, level="info", seconds=4)
rsimgv.request_reload()
rsimgv.action_done(result)
  • host.call runs the same methods as the JSON IPC, on the GTK main thread.
  • ui.idle_add is safe to call from a worker thread and runs the callback on the GTK main thread.
  • ui.connect and ui.timeout_add are tracked and cleaned up on reload.
  • action_done reports an action's result. An IPC actions.run waits for it and returns the result to the client (up to 120 seconds); a dictionary with an error key becomes an error response.
  • Plugins are trusted code. A C-extension crash can terminate rsimgv.

Plugins and the remote control

actions.run with a plugin action blocks until the plugin calls rsimgv.action_done and returns its result:

{"id": 1, "method": "actions.run", "params": {"name": "plugin.com.example.llm-screenshot.analyze"}}
{"id": 1, "result": {"result": "The picture shows ..."}}

plugins.list, plugins.reload, plugins.settings and plugins.set-setting are also available. See Remote control: plugins. A plugin action started from a keybinding or menu does not wait; it reports errors as window notifications.

The bundled LLM Screenshot plugin

Open a picture or video and press Ctrl+Alt+L, or choose Analyze with LLM from the main menu. The viewer's current picture or video frame is sent to an OpenAI-compatible vision model, and the description appears in a persistent overlay notification and in the sidebar panel.

Set the endpoint, model, prompt and limits on the Plugins page, or in $XDG_CONFIG_HOME/rsimgv/plugins/com.example.llm-screenshot/config.json:

{
  "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini",
  "prompt": "Describe this image and identify anything notable about it.",
  "max_tokens": 500,
  "timeout_seconds": 60,
  "api_key_env": "OPENAI_API_KEY"
}

The API key is read from the environment variable named by api_key_env; it is never stored in the config file.

The bundled AI Upscale plugin

au.topher.upscale runs an ncnn/Vulkan upscaler (upscayl-bin or realesrgan-ncnn-vulkan) on the viewed or selected picture and keeps the result in rsimgv's data folder, where the viewer shows it in place of the original. Press Ctrl+Alt+U or choose Upscale picture from the main menu. In the viewer, U switches between the original and the upscaled copy, and Shift+U compares them either side of a draggable divider. The plugin's README lists its requirements and settings.

The bundled LLM Chat plugin

au.topher.llm-chat adds a persistent chat to a sidebar beside the browse view, and over the picture in the viewer; Ctrl+Alt+C shows or hides it. Each message goes to an OpenAI-compatible vision model along with the viewer's current picture or frame, its file name and its metadata, and the picture is shrunk to 768 pixels and sent as a JPEG. Replies are shown as markdown with the model's reasoning, and can be read aloud.

  • The model can use tools to keep and forget memories between chats, and to control the viewer: zoom, next and previous, play and pause.
  • Voice input and spoken replies can use an HTTP endpoint or a local program such as whisper-cli or piper. Ctrl+Alt+V starts a hands-free conversation that listens for speech, sends it and speaks the reply.
  • Messages show names and the picture that was sent, with hover actions to replay, regenerate or delete them, and a button to jump to the latest. The chat's width in the sidebar is window.chat-width.

The plugin's README lists its settings.

The bundled MCP Server plugin

au.topher.mcp-server serves the Model Context Protocol on http://127.0.0.1:8765/mcp (streamable HTTP), so an MCP client can browse folders, drive the viewer, read what it shows and change settings. It offers 38 tools, each annotated as read-only or not, and rsimgv must be running with a window open.

  • Look: get_status is the place to start, then view_info, view_screenshot, get_thumbnails, file information and state, the playlist and the marked files.
  • Browse and view: list and search files, open folders, step through them, open items, and control the picture and video viewer, slideshow and playlist.
  • Everything else: list_actions finds an action and run_action runs it. Actions that open dialogs, quit, need a pointer or depend on keyboard focus are refused, and settings under plugins. cannot be changed.

Connect Claude Code with:

claude mcp add --transport http rsimgv http://127.0.0.1:8765/mcp

The plugin's settings, opened from the button on its row, set the port, the listen address, a bearer token and a read-only mode that hides every tool that changes anything. It listens on the loopback interface only by default. A non-loopback address, such as 0.0.0.0 for Open WebUI in a container, requires a token, and the server refuses to start without one. The tools can run actions and change settings, and the server speaks plain HTTP, so keep it off untrusted networks. In Open WebUI, add it under Admin Settings → External Tools as an MCP (Streamable HTTP) server with the token as a bearer credential. The plugin's README and TOOLS.md list every tool and its arguments.

Limits

  • Hot reload re-imports Python modules; C extensions and GObject types from earlier generations stay loaded for the process lifetime.
  • A plugin stuck in a loop blocks the GTK thread.
  • Native Rust plugins are not implemented yet.
